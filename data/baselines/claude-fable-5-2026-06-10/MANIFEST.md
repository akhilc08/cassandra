# Baseline: claude-fable-5 (frozen 2026-06-10)

The original validated backtest, preserved before re-baselining the forecaster onto
OpenAI. **This is the result the README's headline claim refers to.** Nothing in this
directory is regenerated by any pipeline stage — it is a frozen snapshot.

Archived 2026-08-05.

## Headline result

Leak-controlled time-machine backtest, 959 resolved Polymarket markets,
train/test split at `2026-05-01`.

| | train | test (out-of-sample) |
|---|---|---|
| markets | 687 | 272 |
| trades | 342 | **144** |
| staked | $34,200 | $14,400 |
| P&L | +$6,760.14 | **+$4,394.90** |
| ROI | +19.77% | **+30.52%** |
| 90% ROI CI (as archived) | — | **+7.97% … +55.40%** |
| 90% ROI CI (corrected, event-clustered) | — | **+5.14% … +56.29%** |
| win rate | 43.57% | 45.14% |
| avg edge taken | 17.86% | 17.99% |
| max drawdown | $1,845.74 | $1,170.40 |
| Brier (blend) | 0.2687 | 0.2616 |
| Brier (market) | 0.2047 | 0.2170 |

The test-split CI lower bound is clear of zero under both clusterings. Note the
forecaster is *worse calibrated than the market overall* (Brier 0.2616 vs 0.2170) —
the edge comes from selective disagreement on the subset it trades, not from beating
the market everywhere.

**On the two CIs.** `evaluation.json` in this directory contains the archived
`+7.97% … +55.40%`, and that is left untouched — it is the number that was published.
It is, however, **too narrow**: the bootstrap clusters on `event_id`, and the collect
stage stored `event_id == market_id` for all 959 rows, so it resampled 959 clusters
over 959 markets and was effectively per-trade. Ten correlated "BTC below strike" bets
counted as ten independent observations. Recomputing with keys derived from the event
slug gives `+5.14% … +56.29%`. Point estimates are unaffected.

```bash
scripts/backtest.py evaluate --cluster stored    # reproduces evaluation.json exactly
scripts/backtest.py evaluate --cluster derived   # -> data/backtest/evaluation.derived.json
```

## Frozen parameters

Tuned on the train split only, then applied unchanged to test:

```
alpha           = 1.0     # no shrinkage toward market
threshold (tau) = 0.08
slippage        = 0.01
min_price       = 0.03
max_price       = 0.97
max_divergence  = 0.35
evidence_gate   = None
stake           = 100.0   # flat
kelly_fraction  = 0.25
kelly_cap       = 0.05
```

**These values are calibrated to `claude-fable-5`'s probability distribution.** They
are not transferable to a different forecaster — a model with different calibration
has a different optimal shrinkage and threshold. Any new model must re-tune on the
train split.

## Why this was never confirmed live

A forward paper-trading test ran on 2026-06-10 and produced 3 settled trades
(−$159.15). Every subsequent scan failed: it ran from a laptop crontab, and macOS
cron cannot reach the login Keychain where the Claude Code OAuth token lives, so
`claude -p` exited non-zero with empty stderr on every invocation for seven weeks.
The pipeline itself was correct end-to-end — only the trigger was broken. The 3
trades carry no statistical information.

The +30.52% therefore remains **backtest-only, never confirmed on live order books.**
